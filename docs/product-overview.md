# KnowledgeHub AI 产品概览

## 产品定位

KnowledgeHub AI 是一个企业知识库与业务助手平台，用于把静态文档知识和结构化业务查询能力放到同一工作台中。它适合以下场景：

- 产品团队整理产品说明、版本能力和常见问答
- 售后团队查询退款、交付、支持政策
- 实施团队沉淀部署条件、接入流程和故障处理手册
- 业务团队在问答过程中补充查询订单、物流或退款状态

## 典型使用场景

### 场景一：知识问答

业务人员提问“企业标准退款规则是什么？”，系统会只在当前知识库内检索相关文档分片，返回答案和来源片段。

### 场景二：无依据拒答

业务人员提问“知识库里有没有加班餐补标准？”，如果当前知识库没有相关内容，系统统一回复“知识库未提供足够依据”。

### 场景三：知识检索 + 业务查询

业务人员提问“查询 ORD-2026-0001 当前状态”，系统会返回业务查询结果，并在前端展示工具调用记录。

### 场景四：Agent 执行轨迹

业务人员完成一次问答后，可以在工作台看到本次执行经过了哪些步骤，包括知识库检索、工具权限判断、业务工具调用、证据校验和模型生成，便于定位回答依据和排查问题。

## 技术架构

### 后端链路

1. 文档上传进入 `KnowledgeBaseService`
2. 统一解析层按文件类型提取文本
3. `DocumentChunker` 进行清洗与 chunk 切分
4. 文档与 chunk 落入 PostgreSQL
5. 向量检索可用时写入 pgvector；不可用时保留关键词检索兜底
6. `AgentService` 创建 agent run，记录 RAG 检索、工具调用、guardrail 和 LLM 生成步骤
7. 问答接口按知识库过滤召回结果，再交由模型生成回答
8. 如果问题中包含订单号且用户具备工具权限，则补充业务查询工具结果
9. `agent_runs / agent_steps` 与审计日志共同记录执行轨迹

### 前端工作台

- 知识问答：查看回答、来源、工具调用记录和 Agent 执行轨迹
- 文档中心：上传文档、查看状态、重建索引
- 知识库管理：创建并切换不同知识库

## 当前产品化骨架

- 多知识库数据模型
- 文档类型扩展：TXT、Markdown、PDF、DOCX
- 入库状态管理：`pending / indexing / indexed / failed`
- 问答按知识库隔离
- 来源可追溯与工具调用可观测
- 轻量 Agent 编排：RAG、Tool Calling、Prompt 约束、权限控制、执行轨迹
- MCP Server 基础接入：复用 Spring AI `@Tool` 暴露工具能力
- Actuator/Micrometer：提供基础运行指标入口

## LangGraph4j 取舍

LangGraph4j 更适合复杂的有状态图编排，例如多智能体协作、Planner-Executor、人工确认节点、循环执行和失败恢复。当前项目的核心是企业知识库问答、受控业务工具调用、权限审计和可观测性，因此先采用 Spring AI 原生 Tool Calling + Agent Run/Step 记录实现轻量智能体链路。后续如果要扩展为多步骤规划型 Agent，可以将当前 `AgentService` 的步骤拆成 LangGraph4j 节点。

## 可扩展方向

- 混合检索、Rerank 和 Query Rewrite
- 文档级 metadata filter 与权限控制
- 异步任务调度、失败重试和审计日志
- 更完整的业务工具体系，例如工单、合同、发票、项目节点查询
- LangGraph4j 图编排、Human-in-the-loop、Agent Memory 和 SSE 流式输出
