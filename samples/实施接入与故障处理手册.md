# KnowledgeHub AI 实施接入与故障处理手册

## 生效范围

适用于 KnowledgeHub AI 环境初始化、向量检索启用、数据接入评估和常见故障排查。

## 适用对象

实施顾问、解决方案架构师、平台运维、数据库管理员。

## 正文条款

### 1. 启用向量检索前的数据库条件

在 PostgreSQL 中启用向量检索前，需要满足以下条件：

1. PostgreSQL 版本不低于 15，建议使用 17。
2. 数据库已安装并启用 `pgvector` 扩展。
3. 向量表所在库具备建表、建索引和写入权限。
4. 向量维度必须与当前 embedding 模型一致；默认 `text-embedding-v4` 配置为 `1024` 维。
5. 数据库连接池与大批量写入策略需预留足够资源，避免文档入库时长时间阻塞。

### 2. 文档入库流程

上传文档后，平台按以下状态流转：

- `pending`：已接收上传请求，等待开始处理
- `indexing`：正在解析文本、切分 chunk、写入数据库
- `indexed`：入库完成，可参与问答
- `failed`：解析失败或入库失败，可根据错误信息定位问题

### 3. 数据源接入原则

标准交付默认覆盖 PostgreSQL、MySQL 和企业内部 HTTP API。若客户要求接入 Oracle、Elasticsearch 或其他异构组件，必须进入定制化评估流程，重点核查：

- 驱动与协议要求
- 网络访问路径
- 鉴权方式
- 字段映射规则
- 同步频率与容量预估
- 失败重试和审计要求

### 4. 常见故障处理

#### 4.1 文档上传成功但无法检索

优先检查以下项目：

1. 文档状态是否为 `indexed`
2. 目标知识库是否选择正确
3. `pgvector` 是否可用，或系统是否已自动回落到关键词检索
4. 文档内容是否解析为空，导致没有有效 chunk

#### 4.2 PDF / DOCX 解析失败

可能原因包括：

- 文件损坏
- 扫描件中没有可提取文本
- 文档经过异常加密或格式不规范

此时应根据错误信息定位具体文件，并建议用户重新导出或提供可编辑源文件。

## 常见问答

### Q1：接入向量检索前需要满足哪些数据库条件？

A：至少需要 PostgreSQL 15+、已启用 `pgvector`、具备建表建索引权限，并保证向量维度与 embedding 模型一致。

### Q2：客户要求接入 Oracle / Elasticsearch 时怎么办？

A：需要先走定制化接入评估流程，确认驱动、网络、鉴权、字段映射和同步策略，评估通过后再安排实施。

### Q3：文档状态为 failed 时应该先看什么？

A：先看错误信息，再结合文件类型判断是解析失败、空文本还是数据库写入失败。
